1.Positioning — what this thing is

Notionharness is Notion + Slack + an agent harness in one Next.js app, with a plugin system that lets teams plug their own tools in. Every other product assumes the other two don't exist — that is the seam we sit in.

Knowledge (Notion-shaped)

BlockSuite pages with custom blocks: agent-session, run-card, task, suggestion-marks. Pages are first-class; an artifact is a pointer to a page.

collections/Pages.ts collections/Databases.ts lib/blocksuite-doc.ts

Communication (Slack-shaped)

Channels, threads, mentions, reactions, unread, approvals. Agents are slots in the same channel as humans.

lib/broker/channels.ts components/teams/* lib/broker/messages.ts

Execution (Cursor-shaped)

ACP runtimes (Hermes, Claude Code, Codex…), per-run worktrees, tool cards, terminals, streaming with the RunEvent contract.

lib/runtimes/* lib/dispatcher/worker.ts lib/run-worktrees/*

The seam: pages can carry agent transcripts as a block; channels can carry pages as cards; runs can cite pages and channels. Three systems with one data model underneath, not three products glued together.

3.The Seam — where the three products overlap

This Venn is the strategic claim. Each circle is a market; the overlap is the surface area this product owns alone.

Triple overlap = ours. The dashed circle is what competitors have to build to match.

Knowledge ∩ Communication

A page embedded inside a channel as a card; a message with a "convert to page" action that reuses the transcript-to-blocks path in lib/transcript/to-page.ts. Cited at the message level so an edit to the page shows through.

Knowledge ∩ Execution

An affine:embed-run-card, affine:embed-task, affine:embed-agent-session block in a page carries the run's state live. R8 takes this further — the artifact is the page.

Communication ∩ Execution

An agent is a slot in the channel (team_members), with presence, inbox, approvals, and a thread of its own. The same agent card appears in the roster.

5.Plugin System — two levels of MCP, by ownership

The hardest design choice in the whole app, made once and recorded in docs/ROADMAP-SERIES.md as D4. The principle is ownership, not transport.

Runtime-level MCP — mirror, not owned

Whatever the agent CLI has already configured. We read it, toggle it, write no ownership into it. hermes mcp add edits behind our back and the mirror reflects that on the next read.

Why mirror-only: storing a copy would be wrong the first time someone ran hermes mcp add on the host.

Plugin-level MCP — owned, in our DB

Workspace row, scoped to specific agents, injected at session/new, gone when the turn ends. Served over HTTP and SSE from this app (not stdio — server processes aren't co-located).

Per-run short-lived credentials via {{RUN_TOKEN}} / {{RUN_ID}} substitution at resolve time. Composio reaches us as a plugin row, no SDK integration written.

ACP, the only interface

There are no adapter classes. lib/hermes/acp-client.ts is the ACP stdio transport. Capabilities, modes, models and config options come from the initialize response and are stored verbatim. Tri-state "unknown / supported / not" is the right call — see R1.A.3.

R1 status. The 12-files extraction is partial. Latent import cycle (worker.ts ← acp-client) and the client-bundle audit (R1.5) are flagged in the roadmap as "find out before moving". Until R1 is done, registering a second runtime from the UI is not a thing.

Worktree lifecycle

Per-run disposable worktree under lib/run-worktrees/. Retention is armed manually via RUN_WORKTREE_AUTO_RECLAIM=true — deleting a run's diff is irreversible and only the machine's owner knows which old run still matters. Measured on this box: 79 checkouts, 59 reclaimable, 184 MB.

9.Latency Budget — D0 outranks every other decision

D0 is recorded at the top of docs/ROADMAP-SERIES.md. The rules and what they cost:

What is forbidden

No CRDT on the streaming path. Feeds are virtualised React lists over the typed RunEvent stream. Per-block CRDT is correct and cheap; per-token is catastrophic.

No round trip on the send path. Pressing Enter paints immediately.

No polling where a push exists. The broker has LISTEN/NOTIFY and SSE.

No blocking first render on an external process.

No unbounded lists.

Known debt, carried openly

getSidebarPages — second query on every workspace render to exclude task documents. Fold in.

readConfigSubset — fetches whole config from runtime, projects down. Cache per profile.

Runtime dashboard server cold-starts ~3 s. Warm in background, show "warming" not blank.

Work session rail 5 s interval. Should ride the event stream.

Reveal buffer spreads large chunks over a few frames. Keep bounded, no-op under reduced motion.
